# سامانه مدیریت پروژه سمپاد

سامانه فارسی و راست‌چین برای پیگیری ۱۵۹ تعهد استخراج‌شده از صفحات ۶ تا ۱۶ سند RFP سمپاد.

## امکانات

- داشبورد پیشرفت، فعالیت‌های معوق و اشکالات باز
- ثبت وضعیت، درصد پیشرفت، مسئول و ددلاین
- تأیید مستقل ناظر و بهره‌بردار
- ثبت اشکالات، اقدامات اصلاحی، جلسات و مصوبات
- نقش‌های مدیر پروژه، پیمانکار، بهره‌بردار، ناظر و مشاهده‌گر
- ذخیره اطلاعات و تاریخچه تغییرات در Cloudflare D1
- جست‌وجو، فیلتر، صفحه‌بندی و رابط واکنش‌گرا

## پیش‌نیازها

- Node.js نسخه 22.13 یا جدیدتر
- حساب Cloudflare با Workers، D1 و Zero Trust Access
- یک دامنه یا زیردامنه متصل به Cloudflare

## راه‌اندازی

```bash
npm ci
npx wrangler login
npx wrangler d1 create project-manage
```

دستورهای اصلی پروژه مستقل از Bash نوشته شده‌اند و در PowerShell ویندوز،
Linux و macOS قابل اجرا هستند. در ویندوز دستورات را مستقیماً در PowerShell
اجرا کنید و نیازی به اجرای فایل‌های پوشه `scripts` ندارید.

شناسه پایگاه داده ساخته‌شده را در فایل `wrangler.jsonc` به‌جای
`REPLACE_WITH_YOUR_D1_DATABASE_ID` قرار دهید. سپس migration را اجرا کنید:

```bash
npx wrangler d1 migrations apply project-manage --remote --config wrangler.jsonc
npm run build
npm run deploy:cloudflare
```

بعد از انتشار، دامنه دلخواه را از بخش Routes & Domains همان Worker متصل کنید.

## احراز هویت

سامانه برای استفاده سازمانی طراحی شده و باید پشت Cloudflare Access قرار گیرد.
Access ایمیل کاربر را در هدر `Cf-Access-Authenticated-User-Email` ارسال می‌کند.
در استقرار پشت reverse proxy نیز می‌توانید هدر مورد اعتماد
`X-Authenticated-User-Email` را تنظیم کنید. این هدر نباید مستقیماً از اینترنت قابل جعل باشد.

اولین کاربری که وارد پایگاه داده خالی شود نقش «مدیر پروژه» می‌گیرد. مدیر پروژه پس از ورود
می‌تواند نقش سایر کاربران را از بخش «کاربران» تعیین کند.

## توسعه محلی

ساخت پروژه و کنترل TypeScript:

```bash
npm run build
```

اجرای محیط توسعه:

```bash
npm run dev
```

فایل‌های schema در `db/schema.ts` و migrationهای قابل اجرا در پوشه `drizzle` قرار دارند.

## نکات امنیتی

- سامانه را بدون Cloudflare Access یا reverse proxy احرازهویت‌شده عمومی نکنید.
- فایل `wrangler.jsonc` نباید شامل رمز یا توکن باشد.
- پیش از بهره‌برداری، از پایگاه داده D1 نسخه پشتیبان تهیه و سیاست نگهداری آن را مشخص کنید.
